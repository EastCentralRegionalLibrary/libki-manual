== Backup & restoration

WARNING: It is *HIGHLY* advised to only perform  backups and restorations of the database while the system is not being used!

=== Backing up

The backup program is intended to be used on a server installed with `install.sh`, which has a `libki` user. Run it as root.

IMPORTANT: Making a backup *stops the Libki service* while it runs and starts it again afterwards, so clients cannot log in for a short time.

Each backup is a single archive containing the database dump (`db.sql`), a tarball of the server files (`libki-server.tar.gz`) and the init script (`init`). Archives are written to `/home/libki/backups`.

Please note that this will only create local backups. It is advised to transfer them to a safe location.

==== Make a backup manually

Run `libki-backup`.

The file name contains the date and time, for example `libki_backup_180706_19.30.tar.gz`.

==== Make automatic backups

The backup program features a silent mode, perfect for when you don't want any user input or text output. Run `libki-backup -s` to run it in silent mode.

Automatic backups work the same way as the manual backups, but do not print anything.

To run backups on a schedule, use root's crontab: run `sudo crontab -e` and add a schedule at the bottom of the file.

*Crontab examples*

Daily backup at 02:00:

[source,bash]
----
0 2 * * * /usr/local/bin/libki-backup -s
----

Backup every Sunday evening:

[source,bash]
----
0 21 * * SUN /usr/local/bin/libki-backup -s
----

Backup the first date in every month at 01.15:

[source,bash]
----
15 1 1 * * /usr/local/bin/libki-backup -s
----

NOTE: The backup program dumps a database named `libki` using root's database access. It does not back up a Docker deployment; for Docker, back up the `db_data` volume or use `mysqldump` against the `db` container.

=== Restoring a backup

WARNING: Restoring *deletes the current database and the current server files*, then replaces them with the contents of the archive. Make sure you really want this.

Run `libki-restore` as root with the path of the backup archive. It must be a `.tar.gz` file made by `libki-backup`; a bare `.sql` dump is rejected.

[source,bash]
----
libki-restore /home/libki/backups/libki_backup_180706_19.30.tar.gz
----

The program asks for confirmation, stops the service, restores the database, the server files and the init script, and starts the service again. Your server is now at the point it was when the backup was created.

=== Restoring only the database

If you only want the database from a backup, extract `db.sql` from the archive and load it yourself:

[source,bash]
----
service libki stop
mkdir /tmp/restore && tar -C /tmp/restore -pxzf /home/libki/backups/libki_backup_180706_19.30.tar.gz db.sql
mysql -e "DROP DATABASE libki; CREATE DATABASE libki DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
mysql libki < /tmp/restore/db.sql
service libki start
----
